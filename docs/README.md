# HTTP Client Package {#http-client-package}

`switon/http-client` gives Switon apps one HTTP client contract with JSON-first helpers, typed failures, and response helpers.

**Key features:**

- **One client contract:** inject `Switon\HttpClient\HttpClientInterface` into services.
- **JSON-first shortcuts:** `get()`, `post()`, `put()`, `patch()`, and `delete()` are the normal path for JSON APIs.
- **Raw requests when needed:** `request()` and `head()` keep the raw transport path available.
- **Useful response helpers:** `Response` gives `json()`, `text()`, `status()`, `header()`, and raw headers.
- **Request-scoped transport options:** `RequestOptions` handles timeout, proxy, CA file, and TLS verification.
- **Multipart uploads:** `LocalFile` and `MemoryFile` support file bodies.
- **Pooled engines:** repeated calls to the same origin reuse engines through the client pool.

## Installation {#installation}

**Requirements:** PHP 8.3+, `ext-curl`

```bash
composer require switon/http-client
```

## Quick Start {#quick-start}

Inject `Switon\HttpClient\HttpClientInterface` and call a JSON shortcut method.

```php
namespace App\Service;

use Switon\Core\Attribute\Autowired;
use Switon\HttpClient\HttpClientInterface;

class UserService
{
    #[Autowired] protected HttpClientInterface $httpClient;

    public function featuredUsers(): array
    {
        return $this->httpClient
            ->get('https://api.example.com/users/featured')
            ->json();
    }
}
```

Use `RequestOptions::of(3)` when you only need a timeout override.
The client also keeps a small engine pool per origin; `pool_size` controls the default capacity.

## Core Concepts {#core-concepts}

### JSON-First Requests {#json-first-requests}

The shortcut methods are the common path for JSON APIs.

- array bodies are encoded as JSON
- shortcut methods add JSON-friendly headers such as `Accept: application/json` and `X-Requested-With: XMLHttpRequest`
- JSON responses are parsed into arrays with `json()`
- `request()` stays raw for the method/body path, but still throws on non-2xx responses
- `head()` uses the same transport path as `request()` and skips JSON parsing entirely
- string bodies are only treated as JSON automatically when they look like an object or array payload

Use `request()` for non-JSON endpoints or when you want full control over method and body handling.

### Responses {#responses}

`Response` gives a small set of stable accessors:

- `json()` for decoded JSON data
- `text()` for UTF-8 text
- `status()` for the HTTP status code
- `header()` for one header value
- `rawHeaders()` for the final header block after redirects

`getCookies()` reads `Set-Cookie` headers when you need cookie values.

### Request Options {#request-options}

`RequestOptions` is the per-request override layer.

- `timeout`
- `connect_timeout`
- `proxy`
- `cafile`
- `verify_peer`

`RequestOptions::of(3)` is shorthand for `['timeout' => 3]`.
If `connect_timeout` is omitted, the client keeps its own default `connect_timeout` value.

### Pooling {#pooling}

The client pools engines by request origin.

- the pool is keyed by scheme, host, and port
- `pool_size` controls the default capacity for each origin
- the borrow timeout follows the request timeout

### Uploads {#uploads}

Use file payloads when the request body contains files.

- `LocalFile` reads from disk at send time
- `MemoryFile` sends generated bytes without writing a file first

### Lifecycle Hooks {#lifecycle-hooks}

The client emits `HttpClientStart`, `HttpClientRequesting`, `HttpClientRequested`, `HttpClientSuccess` / `HttpClientError`, and `HttpClientComplete`.
Use them for tracing, metrics, or lightweight request observability.

## Configuration {#configuration}

Use `switon.yml` for the request defaults that should stay near the app boundary.

```yaml
# switon.yml
Switon\HttpClient\HttpClientInterface:
  timeout: 3
  connect_timeout: 1
  verify_peer: true
  pool_size: 4
```

## Keep in Mind {#keep-in-mind}

- Use `request()` only when the endpoint is not JSON or when you need the raw method path.
- Use `json()` only after a JSON response is expected.
- Use `LocalFile` for disk-backed uploads and `MemoryFile` for in-memory payloads.
- Use the array URL form when you want to append query parameters to a base URL.
- Check `RequestOptions` first when a request is too slow, too strict, or routed through a proxy.
